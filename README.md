## 📂 폴더 구조
직접 만드는 모든 작업물은 `_Project/` 폴더 내부에서만 관리합니다.
```text
Assets/
├── _Project/
│   ├── Animations/   # 애니메이션 컨트롤러 및 애니메이션 클립
│   ├── Art/          # 스프라이트, 일러스트, UI 소스 등 원본 이미지
│   ├── Audio/        # 배경음(BGM), 효과음(SFX) 등 사운드 소스
│   ├── Prefabs/      # 재사용 가능한 프리팹 (Scripts 구조와 매칭)
│   ├── Scenes/       # 메인 게임, 엔딩 컷씬 등 주요 씬
│   └── Scripts/      # 기능 명세서 기반 스크립트 폴더
│       ├── Core/     # 게임 루프, 데이터 매니저 등 시스템 코드
│       ├── Office/   # (DSK_) 노이즈 퍼즐, 보류함 등 '업무' 기능
│       ├── Player/   # 플레이어 조작, 이동, 입력 포커스 처리
│       ├── Puzzle/   # (ESC_) 암호/퍼즐 기능
│       ├── System/   # (SYS_) 전력 소모, 하루 카운트, 정산 시스템
│       └── UI/       # (UI_) HUD 연출, 엔딩 분기 스크린 전환
└── ThirdParty/       # 에셋 스토어 등 외부 플러그인 (터치 금지!)
```

## 🔗 협업 방식 (GitHub Flow)
1. **브랜치 규칙**: Branch Convention 참고
2. **작업 순서**: 
   - `main`에서 최신 코드 `pull`
   - 새로운 브랜치 생성 후 작업
   - 작업 완료 후 `push` 및 **Pull Request(PR)** 생성
   - 팀원 리뷰 후 `merge`

## 📌 Git Convention

### 🔵 Commit Convention

- `Feat` : 새로운 기능 추가
- `Fix` : 코드 및 내부 파일 수정
- `Build`: 빌드 시스템이나 외부 패키지 의존성에 변화를 준 경우
- `Docs`: 문서 또는 주석만 바뀐 경우
- `Del` : 쓸모없는 코드 혹은 파일 삭제
- `Move` : 프로젝트 파일 및 코드 위치 변경
- `Rename` : 파일 이름 변경
- `Merge` : 브랜치 병합 및 충돌 해결
- `Perf`: **성능 향상**을 위한 코드 변경
- `Refactor`: 버그 픽스나 새 기능 추가 또는 기존 기능 수정, 성능 향상 용도가 **아닌** 코드 변경 (기능 상의 변화가 없는 경우)
- `Style`: 문법 오류 해결, 이름 변경 등 코드 자체의 변경이 없는 수정
- `Test`: 새 테스트 추가 또는 존재하는 테스트 수정
- `Ci` : CI관련 설정 수정에 대한 커밋
- `Chore` : 그 외 자잘한 수정에 대한 커밋

### 커밋 예시

```
<type>(<scope>): <subject>          -- 헤더
<BLANK LINE>
<body>                              -- 본문
```

ex)

```
Fix: 시험 종료 기능 수정

[본문(선택 사항)]
```

<br>

### 🔵 Branch Convention

- `main` : 최종 배포 브랜치
- `feat` : 기능 단위 개발
- `fix` : 버그 및 오류 수정
- `docs` : 문서 및 주석 수정
- `chore` : 설정, 데이터 작업 등 기타 변경

### 브랜치 명 예시

- feat/기능 이름-이슈번호
  - ex) `feat/header-21`

<br>

### 🔵 Issue Convention

> Issue 타입은 커밋 컨벤션을 기준으로 하여 작업 성격을 명확히 구분했습니다.

- Feat : 새로운 기능 추가
- Fix : 버그, 오류 해결
- Build: 빌드 시스템이나 외부 패키지 의존성에 변화를 준 경우
- Docs: 문서 또는 주석만 바뀐 경우
- Refactor: 버그 픽스나 새 기능 추가 또는 기존 기능 수정, 성능 향상 용도가 **아닌** 코드 변경 (기능 상의 변화가 없는 경우)
- Chore : 그 외 자잘한 수정에 대한 커밋

### 이슈 명 예시

- 이슈 항목: 개발 내용
  - ex) `Feat: Header 구현`

## ⚠️ 필독 사항
1. **작업물 위치**: 본인 작업물은 반드시 `_Project/` 내부의 알맞은 하위 폴더에 생성합니다.
   - 외부 플러그인이나 무료 에셋을 가져올 때만 `ThirdParty/` 폴더를 이용합니다.

2. **빈 폴더 유지**: 빈 폴더가 Git에서 유실되지 않도록 `.gitkeep` 파일은 함부로 삭제하지 마세요.
